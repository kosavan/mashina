# Распознавание документов — разработка релиза 2.0

Функция ещё не готова для использования. Сейчас реализованы проверяемые внутренние
границы данных и изолированная подготовка изображений/PDF. Кнопки распознавания,
обращения к модели и запись распознанных операций пока не подключены.
Обычные документы, расходы и офлайн-ввод продолжают работать.

## Опциональные зависимости

Для разработки и тестов:

```powershell
uv sync --frozen --extra dev --extra recognition
.venv/Scripts/python.exe -X utf8 -m pytest -q backend/tests/test_recognition_models.py backend/tests/test_recognition_media.py
```

Обычный образ Docker не включает PDFium. Для образа с библиотекой рендеринга:

```sh
docker build --build-arg MASHINA_RECOGNITION=1 -t mashina:recognition .
```

Установка библиотеки сама по себе не включает распознавание и ничего никуда не
отправляет. Модель, её веса и отдельный сервер обработки не устанавливаются.

## Границы обработки

Источник до 20 МБ; JPEG/PNG и PDF, до 100 страниц в документе и до пяти выбранных
страниц. Зашифрованные PDF, анимация и повреждённые источники отклоняются.
Изображение нормализуется в JPEG без EXIF/ICC и с учётом ориентации; прозрачность
заменяется белым фоном. Максимальная сторона — 1600 px, результат — до 2 МБ на
страницу. Сканированные PDF поддерживаются рендерингом, извлечение текста не требуется.

Нативная обработка выполняется в одноразовом процессе с тайм-аутом 30 секунд;
на Linux дополнительно ограничены адресное пространство 384 МБ, CPU 20 секунд,
размер выходного файла 2 МБ и отключены core dumps. Это контроль ресурсов и
жизненного цикла, а не полноценная песочница безопасности. Обновляйте библиотеки
и сохраняйте ограничения контейнера. На Windows действуют тайм-аут и проверки
размеров, но Linux resource limits недоступны.

## Планируемая модель доверия

Обработка будет необязательной, выключенной по умолчанию, с фиксированными
серверными настройками процессора и явным согласием на отправку выбранных страниц.
Видимые на документе личные данные передаются выбранному процессору; автоматическое
обезличивание не обещается. Никакая история гаража или другие документы не добавляются.

Для локального Ollama необходимо выбрать установленную локальную vision-модель и
отключить cloud (`OLLAMA_NO_CLOUD=1` с перезапуском): один адрес localhost не
гарантирует локальное выполнение. Совместимость vision/structured outputs и скорость
зависят от модели и оборудования. Ошибки не должны приводить к скрытому повторному
запросу, загрузке модели или переходу на облако.

Вывод модели всегда будет непроверенным редактируемым предложением. Отсутствующие
суммы, цены и даты остаются пустыми; финансовая запись требует явной проверки.
Инструкции из документа не исполняются. Деньги проверяются общей точной моделью
MASHINA; несовпадение итога и позиций требует исправления, без выдуманной доплаты.

модели отдельно определяется её поставщиком.
