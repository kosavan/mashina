# Источники VIN, госномеров и запчастей

Русский · [English](vehicle-source-research.md) · [Роудмап](roadmap.ru.md)

Первое исследование: **19 октября 2026 года**. Интеграции пока не реализованы.
VIN, госномера, гараж и ключи владельца никуда не отправлялись. Аккаунты,
подписки и дополнительные серверные службы не создавались.

## Что удалось установить

| Источник | Данные и страны | Доступ и ограничения | Что проверено |
|---|---|---|---|
| [NHTSA vPIC](https://vpic.nhtsa.dot.gov/api/Home/Index) | Марка, модель, год, часть характеристик двигателя; преимущественно машины для рынка США | Публичный API без ключа в проверенных запросах; действует ограничение нагрузки. Другие рынки могут распознаваться неполно | Пример неполного VIN из документации: HTTP 200, BMW X3, 2011, 3 л, шесть цилиндров, **код 6: неполный VIN** |
| [RDW](https://data.overheid.nl/dataset/11441-open-data-rdw--gekentekende-voertuigen) | Нидерланды: регистрационные характеристики, торговое название, срок техосмотра | Государственный каталог указывает CC0; запросы прошли без ключа. Это не универсальная расшифровка VIN | HTTP 200 для метаданных и трёх публичных полей без госномера |
| [DVLA Vehicle Enquiry](https://developer-portal.driver-vehicle-licensing.api.gov.uk/apis/vehicle-enquiry-service/vehicle-enquiry-service-description.html) | Великобритания: марка, год, объём, топливо, статусы налога и MOT; модель и VIN в описанном ответе отсутствуют | Нужен ключ; **выдача новым пользователям сейчас закрыта** на время обновления сервиса | Только документация |
| [DVSA MOT History](https://documentation.history.mot.api.gov.uk/) | Великобритания: результаты техосмотров, записанный пробег, замечания; охват зависит от класса машины, региона и даты | Заявка, OAuth и API-ключ. Лимиты: 500 000 в день, 15 запросов/с, всплеск до 10 | Только документация; заявку не подавали |
| [Auto.dev](https://www.auto.dev/pricing) | Заявлены VIN разных рынков, двигатель и трансмиссия; возможен частичный ответ | 1000 бесплатных вызовов в месяц в тарифе, но условия ограничивают бесплатное использование в продукте для конечных пользователей | Только документация; российский охват не проверен |
| [Автокод B2B](https://b2bapi.avtocod.ru/docs/about/overview) | Российские отчёты по поддерживаемым идентификаторам | Коммерческий API; формирование отчёта списывает баланс. Повторное чтение готового отчёта не означает бесплатную новую проверку | Только документация; платных запросов не было |
| [TecDoc](https://www.tecalliance.net/solutions/tecdoc) | Идентификация автомобиля и связи с запчастями | Коммерческая лицензия; охват стран и права распространения требуют согласования | Только документация |

[Государственный каталог DVSA](https://findtransportdata.dft.gov.uk/dataset/mot-history-api)
указывает бесплатность и Open Government Licence, но содержит старые сведения о доступе.
Перед интеграцией нужно перепроверить условия; для авторизации и лимитов использовать
[актуальную документацию](https://documentation.history.mot.api.gov.uk/mot-history-api/authentication/)
и [лимиты](https://documentation.history.mot.api.gov.uk/mot-history-api/rate-limits/).

В [условиях Auto.dev](https://www.auto.dev/terms), разделы 4.2–4.4, есть ограничения
на распространение данных, производные базы и бесплатное использование в работающем
продукте. Нельзя считать бесплатный тариф разрешением сохранять ответы в экспортируемом
гараже и бэкапах. До выяснения прав этот сервис не подходит как источник по умолчанию.

Для России стабильный документированный бесплатный государственный API с подтверждёнными
правами использования пока не найден. На [официальном сайте Госавтоинспекции](https://госавтоинспекция.рф/)
есть проверка автомобиля, но наличие формы не даёт разрешения использовать внутренний API.
Возможен переход на официальный сайт по действию владельца; обход CAPTCHA и привязку к
недокументированным запросам не планируем. [DaData](https://dadata.ru/api/clean/vehicle/)
нормализует введённую марку/модель, а не расшифровывает VIN.

## Проверки и границы выводов

[Протокол публичных запросов](research/vehicle-api-probes-2026-10-19.json) содержит
три успешных запроса и выбранные поля. Частичный VIN из примера vPIC нельзя считать
полностью установленной комплектацией, даже при HTTP 200. Запрос RDW подтверждает
доступность выбранных полей, но не проверяет поиск конкретного номера, историю или
точный вариант двигателя. Время ответа измерено однократно и не является гарантией.
Сервисы с ключами, российский охват и точность комплектаций остаются непроверенными.

[Локальные базы vPIC](https://vpic.nhtsa.dot.gov/Downloads) требуют SQL Server либо
PostgreSQL и процедур декодирования; это не готовые таблицы SQLite. Дополнительную
СУБД на домашний сервер ради исследования не устанавливаем. Сначала нужны оценка
ресурсов, прав использования, обновлений и пользы локального декодирования.

Полный открытый источник OEM-номеров и аналогов с доказанной применяемостью пока не
подтверждён. VIN и похожий артикул недостаточны: важны двигатель, коробка, дата выпуска,
рынок и оборудование. Сохранённые вручную детали должны работать без подписки;
неполные совпадения должны оставаться непроверенными.

## Предлагаемый порядок работ

1. Начать с необязательных подсказок характеристик после проверки владельцем; оценить
   vPIC для рынка США. Собрать документированные примеры разных рынков, измерить полноту
   и ошибки. Не придумывать код двигателя или комплектацию по неполному ответу.
2. Отдельно оценить RDW для Нидерландов и DVSA после получения ключей владельцем и
   проверки условий. DVLA пока блокирует выдача ключей. Для России — ручной официальный
   путь либо лицензированный необязательный провайдер. Страну выбирать явно, независимо
   от языка интерфейса.
3. Отправлять идентификатор только по явному запросу владельца с понятным указанием
   внешнего сервиса. Ключи хранить на сервере, идентификаторы скрывать в журналах и ошибках.
   Ограничить размеры ответов, время и повторы; учитывать лимиты без фонового опроса гаража.
4. Показывать источник, дату и неопределённость каждого предложения. Применять только
   выбранные поля, сохраняя ручные значения, ID, права и офлайн-очереди. Пробег из старого
   техосмотра не становится подтверждённым показанием автоматически; расходы и записи
   обслуживания из проверки не создаются.
5. До кэширования подтвердить права хранения, показа, экспорта и бэкапов. Гараж, ручной
   ввод и свои детали сохраняют офлайн-работу. Проверить права доступа, недоступные и
   частичные ответы, языки, повторы, обновление и восстановление.
6. Каталог совместимых деталей выделить в самостоятельный этап: выбрать допустимый
   источник, доказать применяемость на документированных примерах и измерить ресурсы.

Исследование не меняет поведение приложения, схему данных и конфигурацию сервера.
