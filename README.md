# MASHINA

Персональный цифровой гараж: автомобили, расходы, заправки, обслуживание,
документы и напоминания. Русский интерфейс, тёмная и светлая темы,
мобильная навигация и устанавливаемое PWA. Данные остаются на вашем сервере.

## Демогараж

На экране входа нажмите **«Посмотреть демогараж»**. Два вымышленных автомобиля,
восемь месяцев расходов и обслуживания позволяют проверить интерфейс и графики.
Можно добавлять, изменять и удалять записи. Каждый сеанс получает отдельную
временную SQLite-базу и каталог файлов; реальные данные недоступны.
Сброс создаёт новый гараж. Демо удаляется при выходе, перезапуске сервера или
очистке истёкших сеансов (срок — два часа). Это демонстрационные данные,
а не сведения о реальных владельцах. Изображения автомобилей сгенерированы.

## Запуск на Linux

Нужны Docker Engine и Compose. В контейнере работает один процесс приложения;
React собирается заранее, Node на сервере приложения не нужен.

```sh
git clone https://github.com/kosavan/mashina.git
cd mashina
cp .env.example .env
mkdir -p data
sudo chown 10001:10001 data
docker compose up -d --build
docker compose exec mashina /app/.venv/bin/python -m backend.cli create-admin
```

Последняя команда интерактивно создаёт владельца; пароль не выводится.
Откройте `http://localhost:8000`. По умолчанию порт доступен только на сервере.
Для первого входа через веб вместо `create-admin` можно выполнить команду
`bootstrap`: одноразовый код будет записан в `data/.bootstrap-token`.
Прочитайте его локально и введите в форме установки. Не публикуйте этот файл.
Открытой регистрации нет. Сейчас поддерживается один владелец установки.

Для удалённого доступа настройте HTTPS, например по `Caddyfile.example`;
задайте свой `MASHINA_ORIGIN=https://…` и `MASHINA_SECURE_COOKIES=1` в `.env`.
Не открывайте HTTP-порт приложения в интернет. PWA на iPhone устанавливается
из Safari: «Поделиться» → «На экран Домой»; нужен HTTPS (localhost — исключение).
Реальное поведение установки следует проверить на вашем устройстве.

## Данные и обновления

`./data` содержит SQLite, вложения и аварийный архив перед восстановлением.
Каталог переживает пересоздание контейнера. Не удаляйте его при обновлении.
База работает в WAL/FULL, изменения сериализуются, миграции Alembic запускаются
при контролируемом старте. Производственный образ собирает SQLite 3.51.3
с исправлением WAL-reset; старый SQLite в production отклоняется.

```sh
docker compose exec mashina /app/.venv/bin/python -m backend.cli backup --backup-dir /app/data/backups --keep 7
docker compose stop
docker compose build --pull
docker compose up -d
```

Перед обновлением скачайте архив на другой физический диск. Копия рядом с базой
не защищает от потери диска. Нет обязательного фонового планировщика: CLI можно
запускать вашим systemd timer/cron. Число сохраняемых архивов настраивается
`--keep` или `MASHINA_BACKUP_KEEP`. Сохраняйте архивы в закрытом каталоге:
они содержат личную историю и хеш пароля.

## Резервные копии, восстановление и экспорт

В настройках доступны полный ZIP, JSON и CSV связанных сущностей. ZIP содержит
согласованный снимок через SQLite backup API, вложения и SHA-256-манифест.
При восстановлении проверяются пути, размеры, хеши, схема и внешние ключи.
Перед заменой создаётся аварийная копия. Сеансы после восстановления аннулируются.
Веб-восстановление ограничено архивом 200 МБ, вложения — 20 МБ каждое.

Для восстановления CLI сначала остановите приложение:

```sh
docker compose stop
docker compose run --rm --no-deps mashina /app/.venv/bin/python -m backend.cli restore --file /app/data/backups/mashina-YYYYMMDD-HHMMSS.zip
docker compose up -d
```

Проверяйте восстановление на отдельном каталоге/экземпляре до возникновения аварии.
Автотест проверяет сохранность автомобиля, файлов и сброс сеансов после восстановления.
Не копируйте только `mashina.db` во время работы: актуальные данные могут быть в WAL.

## Надёжность расчётов и офлайн

Деньги хранятся в копейках, серверные вычисления используют Decimal. Одна операция
имеет одну финансовую запись, включая заправку и ТО. Разные валюты не суммируются.
Расход топлива вычисляется между полными баками с промежуточными частичными
заправками; пропуск записи разрывает цикл. Недостаточные данные показываются явно.
Цена покупки и продажи отделена от эксплуатационных расходов. Стоимость километра
использует подтверждённый пробег периода владения, а не полный одометр автомобиля.

Ранее открытые страницы и данные доступны офлайн. Расходы, заправки, ТО и пробег
сначала сохраняются в IndexedDB. Очередь переживает перезагрузку, сохраняет порядок
и синхронизируется по стабильным идентификаторам операций. Конфликты версий требуют
явного решения пользователя. Статус виден в интерфейсе. Синхронизация выполняется
при открытом приложении; фоновая работа iOS не гарантируется. Загрузка файлов
требует подключения. Выход очищает локальные личные данные с предупреждением
о неотправленных записях. Приватные API и файлы не кэшируются service worker.

## Разработка и проверки

Python 3.12+, uv, Node 20.18+ (в CI и Docker используется Node 22).

```sh
uv sync --extra dev
npm --prefix frontend ci
uv run uvicorn backend.app:app --reload
# В другом терминале:
npm --prefix frontend run dev
```

Dev-сервер Vite проксирует `/api` на backend. Для production-предпросмотра сначала
выполните `npm --prefix frontend run build`, затем запустите backend заново.

```sh
uv run ruff check backend
uv run pytest
npm --prefix frontend run check
npm --prefix frontend test
npm --prefix frontend run build
cd frontend
npx playwright install chromium
npm run test:e2e
```

Проверки покрывают деньги, топливо, пробег, авторизацию, идемпотентность,
миграции, восстановление файлов, изоляцию демо и мобильные/офлайн-сценарии.
Бюджет основного JS — 180 КБ gzip; аналитика загружается отдельно.
Расчёт 10 000 событий проверяется с бюджетом 1 с на тестовой машине;
это не замер конкретного домашнего сервера. Контейнер ограничен 1 CPU / 512 МБ.

Архитектура, модель, API и приёмка: [specs/001-mashina-platform](specs/001-mashina-platform).
Конституция: [.specify/memory/constitution.md](.specify/memory/constitution.md).
Spec Kit установлен в проект; `.tools` и окружения в Git не публикуются.

## Границы релиза

MVP предназначен для одного владельца. Совместный доступ, шины, бюджеты, импорт,
уведомления и PDF-отчёт относятся к 1.1; AI, бот, OBD-II, банковский импорт и
MCP — к 2.0. Они развиваются отдельными проверяемыми срезами. Обязательных
облачных сервисов, платных API, внешних шрифтов и скрытой телеметрии нет.
