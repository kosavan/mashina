# Plan — optional notification channels
React lazy Notifications settings sheet, FastAPI module backend/notifications.py, SQLite additive migration 004. No app worker/polling. pywebpush performs RFC encryption/VAPID; custom pinned HTTPS transport performs actual egress. filelock coordinates optional CLI dispatcher with restore; normal SQLite backup remains consistent while dispatcher changes only database rows, never uploads.

Dedicated notification_identity singleton stores base64 DER P-256 private/public key in database; full admin backup naturally includes it, ordinary state/export does not. CLI notification-keys generates once, never prints private material. notification_preferences per user (telegram opt-in), push_subscriptions keyed UUID/user with unique endpoint hash, telegram_links one private chat per user, hashed telegram_link_codes, notification_deliveries unique semantic key and state/attempt/timestamps. paused_after_restore identity flag blocks all outbound until local notification-resume. New schema additive; restore validates FKs/config states and pauses, expires links. Legacy snapshot tests truly drop new tables.

GET /notifications status returns only own setup/labels/statuses/journal and public VAPID key. POST /notifications/push registers validated subscription, DELETE by own ID; POST /notifications/push/current resolves only own device ID; logout body carries the current endpoint to remove its own binding before ending the session. POST Telegram code, DELETE Telegram binding, POST explicit journal retry with acknowledge_duplicates flag. Authentication/CSRF/demo guard applies. No private endpoints/chat IDs/tokens in API responses or audit. Telegram bot credentials only environment; code is shown once, stored SHA-256, TTL 600 seconds. CLI optionally receives bounded getUpdates and persists offset; only private message exact code links. One chat cannot bind multiple users accidentally.

Each dispatch builds due owner reminders from fresh state. Cycle hash uses deadline/date/km and completed_at; status soon/overdue, recipient+channel+destination+reminder ID comprise delivery key. Atomic INSERT OR IGNORE and conditional claim prevent duplicates. New claim before outbound, accepted/rejected/uncertain/cancelled states; stale claims become uncertain. Recheck permissions and destination immediately before sending; no DB transaction held across HTTP. 429 delayed bounded retries, unknown needs explicit acknowledgement. Journal rows retain small semantic dedupe tombstones; no private reminder text or payload is stored, and only the latest20 appear in API. At most50 journal records claimed/run and grouped into one generic message per destination; five automatic429 attempts, explicit acknowledged retry resets only the automatic budget and retains the total attempt count. Run caps 50 requests /60 sec; no unbounded loop or sleep.

SSRF: normalized provider URL from strict fixed origins/suffix boundary, HTTPS443, no userinfo/fragment, no IP literal; auth exactly16 bytes and p256dh valid65-byte P-256 point. DNS A/AAAA all globally routable. Custom urllib3 HTTPSConnectionPool on resolved address with assert_hostname/server_hostname and trusted CA, Host original, redirects/retries/proxies disabled, bounded read. pywebpush gets custom requests-session adapter whose post returns bounded requests.Response. Telegram fixed api.telegram.org uses same protected HTTPS primitive, token URL never logged. Test adapters intercept all network operations.

Frontend lazy custom sheet: configuration explanation, provider/privacy consent, per-device subscribe/disconnect, one-time Telegram linking code/expiry, binding disconnect, latest journal+explicit retry confirmation. Notifications never cached in IndexedDB. SW push always shows generic visible notification, notificationclick hardcodes same-origin '/', discards remote payload URLs. Logout removes this device subscription before session clearing; requires online revocation and fails visibly while offline: the HttpOnly server session cannot be revoked by local cleanup. Reduced motion/themes inherited.

Performance: no polling, no app loop. 1000 reminders classify under1sec fixture; at most50 deliveries/run,10 subscriptions/user, latest20 journal items. HTTP connect/read bounded, total run60sec best effort with monotonic deadline before each request; one request may finish up to timeout after deadline. No actual external sends during implementation.

Constitution: shared confirmed reminder rules, exact historical data untouched, default-private consent and typed request models, local durable keys/migrations, optional dependencies only. Research delegated read-only per Spec Kit plan. No unresolved product questions; routine defaults favor privacy and low resource usage.
