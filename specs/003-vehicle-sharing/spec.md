# Feature Specification: MASHINA 1.1 — совместный доступ
**Feature Branch**: codex/mashina-sharing
**Created**: 2026-10-11
**Status**: Ready for planning
**Input**: Запланированный релиз 1.1: совместный доступ с ролями владельца и водителя.

## User Scenarios & Testing
### User Story 1 — Локальные аккаунты (P1)
Администратор создаёт учётную запись для близкого человека без открытой регистрации.
**Independent Test**: Создать водителя, войти другим браузером; до назначения автомобиля гараж пуст.
**Acceptance Scenarios**:
1. Создать пользователя может только администратор. Пароль не возвращается и не появляется в логах.
2. У каждого человека отдельный сеанс, настройки и локальная очередь; выход очищает его данные устройства.
3. Пользователь может изменить собственный пароль с проверкой текущего; старые сеансы аннулируются.
### User Story 2 — Доступ к автомобилю (P1)
Владелец предоставляет доступ к конкретному автомобилю и может его отозвать.
**Independent Test**: Из двух автомобилей поделиться одним; второй недоступен ни через интерфейс, ни по известному ID.
**Acceptance Scenarios**:
1. Водитель читает назначенный автомобиль и его события, создаёт и исправляет свои расходы/заправки/ТО/пробег/заметки.
2. Водитель не меняет профиль, чужие события, права, бюджеты, шины и интервалы; сервер отклоняет прямой запрос.
3. Делегированный владелец управляет историей и настройками назначенного автомобиля; исходный владелец сохраняет контроль.
4. После отзыва новые запросы к машине и файлам запрещены, ожидающие офлайн-операции получают видимую ошибку.
### User Story 3 — Приватные документы и архивы (P1)
Владелец явно решает, какие документы доступны участникам.
**Independent Test**: Личный документ скрыт от водителя; явно общий доступен. Полный архив водителю недоступен.
**Acceptance Scenarios**:
1. Старые и новые документы по умолчанию личные; общий доступ включается владельцем явно.
2. Водитель читает свои загрузки и общие документы назначенных машин; не меняет чужие вложения.
3. JSON/CSV содержат только доступные данные человека. Полный ZIP/восстановление — только администратору.
4. Архивы прежних схем обновляются без потери данных; архив с несколькими пользователями сохраняет роли и хеши, сеансы сбрасываются.

### Edge Cases
Подмена created_by/owner_id, известные чужие UUID, смена роли во время открытой формы, отзыв доступа с офлайн-очередью, повторное предоставление, удаление используемой обложки, личное вложение к общей работе, дубликат username, замена пароля и истёкшие сеансы.

## Requirements
- **FR-001**: Закрытое создание аккаунтов администратором и безопасная смена собственного пароля.
- **FR-002**: Роли owner/driver на конкретный автомобиль с немедленной серверной проверкой.
- **FR-003**: Водитель изменяет только собственные события; автор и собственник назначаются сервером.
- **FR-004**: Участники не получают данные других автомобилей или личные документы.
- **FR-005**: Административные бэкапы отделены от ограниченного личного экспорта.
- **FR-006**: Интерфейс показывает доступные действия и объясняет роль; отказ API не уничтожает черновик.
- **FR-007**: Миграция и восстановление сохраняют историю MVP/первого среза 1.1.

## Key Entities
User (administrator flag), VehicleAccess(vehicle,user,role), immutable event author, attachment visibility and uploader, existing sessions/receipts/audit.

## Success Criteria
- **SC-001**: Матрица ролей проверена для чтения, записи, файлов, экспорта и архива.
- **SC-002**: Сумма общей истории одинакова для разрешённых участников и не дублирует операции.
- **SC-003**: Водитель не получает второй автомобиль даже при известном UUID.
- **SC-004**: После отзыва все новые запросы к автомобилю запрещены.
- **SC-005**: Старые архивы восстанавливаются; роли, авторы и вложения сохраняются в новом архиве.

## Assumptions
Администратор владеет установкой и полными архивами; это не изоляция от владельца сервера. Доступ к ранее сохранённым данным на доверенном офлайн-устройстве нельзя удалённо отозвать до соединения. Участник может иметь собственные автомобили и стать их владельцем; права предоставляются на конкретные машины. Приглашения через email/внешние сервисы не нужны: локальный аккаунт создаётся администратором.
